# Проверка редактора, амперметра и шрифтов — 23.10.2026

## Что наблюдалось в оригинале

Использован установленный TINA-TI 9.3.150 и разрешённый пользователем локальный Win32 oracle. Пользовательский экземпляр с несохранённым документом не закрывался; дальнейшие шрифтовые опыты выполнялись в отдельном, явно выбранном редакторе. `native-oracle.py dialog_file` теперь принимает конкретный HWND и проверяет его принадлежность редактору, чтобы не выбирать чужой экземпляр.

- `attached_wire.TSC` → `attached_wire_native_moved.TSC`: GND–VM, перенос горизонтального участка вверх40. Одна запись, неподвижные выводы, маршрут `200,360 → 200,320 → 440,320 → 440,240`.
- `notched_wire.TSC` → `notched_wire_native_moved.TSC`: захваченный верхний участок выемки перемещён вверх40. Дальние изгибы и дно выемки не перемещаются. Это уточняет прежнее предположение о переносе всей polyline.
- Снимки `native-text-dialog.png`, `native-text-font-dialog.png`: компактный TCSysTextDlg, верхняя панель формул, боковые OK/отмена/справка/шрифт/дополнительные параметры; отдельное окно шрифта. Для нового текста наблюдались Arial8, синий.
- В `text_native18.TSC` уже присутствовал настоящий круглый амперметр type519/v66, AMV. Он использован как донор; AM type547 — другой прибор, указатель тока.
- `text_style_baseline.TSC` и пять `text_native_{bold,italic,bold_italic,underline,strike}.TSC`: изменён один атрибут в настоящем окне «Шрифт». После counted font, по offset p+8: bold1, italic2, combination3, underline4, strike8. Browser updateText даёт точное совпадение всей записи для каждого опыта.
- Ранний `text_style_bold.TSC` имеет неудачное имя: фактически выбран Arial Narrow italic (стиль2). Причина — семейство Arial объединяет дополнительные варианты в списке начертаний. Этот файл не используется как доказательство bold. Контрольные пять файлов созданы по точным названиям вариантов, а не по предполагаемым индексам.
- `round_meter_browser_text.TSC` открыт и пересохранён оригиналом в `round_meter_text_native_resaved.TSC`: настоящий AMV, Times New Roman18, style7, цвет #3366cc; вся текстовая запись сохранена побайтно.

## Реализовано и проверено

- Один провод остаётся одним объектом. Одиночный захваченный ортогональный участок растягивается по наблюдённому правилу; крайние подключённые выводы закреплены. Групповое движение остаётся отдельной операцией. Непрозрачные хвосты записей сохранены; намеренные диагонали не нормализуются.
- Подписи компонентов перетаскиваются отдельно. Для четырёх поворотов меняются только смещения подписи; проверены обратный перенос и отказ при переполнении. Original resave сохраняет подпись браузера.
- Физические клавиши для сочетаний поддерживают русскую раскладку, история не теряется после неудачной правки. Браузерный сценарий проверяет отмену и повтор, включая движение подписи. Постоянная поясняющая плашка с полотна полностью удалена по просьбе пользователя.
- AMV создаётся из настоящего донора; обозначения AM1, AM2… Проверка покрывает все14 объявленных видов: каждый имеет действующий шаблон создания. Вставка, отмена, повтор, сохранение и native reload проверены. ngspice: цепь5В/1кОм показывает +5мА через круглый амперметр.
- Текстовый диалог перестроен по наблюдённой компоновке оригинала. Шрифт, размер, цвет, bold/italic/underline/strike работают в предпросмотре, SVG и TSC. Неизвестные старшие биты стиля и хвосты остаются нетронутыми. Неисследованные формульные кнопки показаны неактивными. Нет пояснений о внутренней записи TSC в диалоге.

## Инструменты и ограничения доказательств

Существующие tina-analysis.json / tina-entry-decompile.json повторно не запускались. Для конкретного вопроса о ресурсах текстового диалога вызван REA inspect_pe_resources. Он отказал: `Resource range is not entirely file-backed in one section` (invalid_request). Полного дерева ресурсов не получено; выводы о текущем интерфейсе основаны на runtime оригинала, не на статике. Observe_native_ui в доступном REA ориентирован на Mach-O; прежняя неподдержка Windows runtime не выдаётся за отсутствие окна TINA.

Computer Use helper в этом сеансе дважды вернул native pipe unavailable. Браузерные проверки проведены в отдельном headless Chromium штатным bundled Playwright, без подключения к пользовательскому профилю. `tools/check-editor-browser.mjs`, команда `npm run test:browser` (нужен работающий Vite и bundled Playwright либо PLAYWRIGHT_PACKAGE).

DeepSeek действительно использован: прежний review attached drag через env backend; затем установленный OpenRouter MCP, модель deepseek/deepseek-v4.1-flash-1017. Первый MCP ответ исчерпал лимит на reasoning, второй с reasoning none дал полезную проверку. Результат `deepseek-meter-text-review.txt`. Его ошибочное утверждение о дополнительном unknown32 после lineCount не принято: парсер и реальные fixtures показывают строки непосредственно после p+16. Модель не меняет файлы самостоятельно; рекомендации проверены локально. Секретов в отправленном запросе и файлах нет.
