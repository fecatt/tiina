1. **`nativeGenerator` phase-overflow / invalid sine range not validated** — sine `phase = parameter + 90` is returned without any finite/range check on `parameter`; only `frequency>0` and `resistance===0` are enforced. `parameter` comes straight from raw float64 and can be `NaN`/`±Inf` (checked finite) but also absurd (e.g. `1e308`), producing invalid `SIN(...)` phase. Propose edge test: build a component with `p+26` = `1e300` (or `-1e300`) and assert `nativeGeneratorWaveform` either rejects or emits a sane phase.

2. **Square branch rejects valid endpoint `parameter === 1/frequency/2`** — the code uses `parameter>=1/frequency/2` to reject, but the comment says the transition extends to `±t` where `t = period/2` is the natural maximum edge; at exactly half-period the two ramps meet at `period/2±s.edge` producing a single-sample spike, which is silent (no throw) but degenerates to zero-width pulse in PWL when `edge == period/2`. Propose edge test: `edge = 1/frequency/2` (exact boundary) must throw rather than silently produce degenerate PWL.

3. **`nativeRectangleWaveform` `cycles` overflow when `stop/period` is huge but finite** — `Math.ceil(stop/period)` can exceed `Number.MAX_SAFE_INTEGER` when `period` is tiny (frequency huge but finite); `cycles>16000` catches large, but for `period = 1e-300` and `stop=1`, `cycles = 1e300`, `>` comparison is fine, but the loop `i<=cycles` is unreachable before throw. However when `stop/period` is `Infinity` (frequency denormal, e.g. `1e-320`, `stop=1`), `cycles = Infinity`, `Infinity > 16000` is true → throw; but if `frequency` is a subnormal so `1/frequency = Infinity`, `cycles = Math.ceil(0) = 0`, loop runs `i=0..0`, produces one period of `PWL` with `period=Infinity` → `t=0`, edge/period etc all `NaN`/`Infinity` in timestamps. Propose edge test: `frequency` subnormal (`5e-324`) must reject or not emit `Infinity` timestamps.

4. **`nativeGeneratorWaveform` for sine silently emits `phase` from `parameter+90` even when `parameter` is out of any sane range; also `SIN` ignores `resistance` beyond the `===0` check but that's already required** — actually the concrete bug: **sine path never validates `parameter` at all** (only the square path does), so a native sine record with `p+26` garbage passes through. Propose edge test: set `p+26` to `1e-300` (finite) on a sine record; assert the emitted `SIN(...)` is accepted by the simulator or the code rejects.

5. **`job.netlist.replace(/^\.tran /m, ...)` fails when leading whitespace precedes `.tran`** — the regex anchors `^\.tran ` at line start with no tolerance for leading spaces/tabs, common in SPICE decks after indentation; then `.ic` is silently not inserted and no error is raised (the `replace` simply returns the original string). Propose edge test: netlist containing `"  .tran 0 1m\n"` (leading spaces) must either insert `.ic` or throw, not silently no-op.
