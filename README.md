# Браузерная TINA

Цель — полный перенос TINA-TI с настоящими файлами TSC для оригинальной программы. Сейчас реализована часть редактора, компонентов и анализов. Сайт не объявлен готовой заменой TINA для всех лабораторных.

- [Карта технических материалов](docs/README.md) — исследования, доказательства и история.
- [Правила проекта](AGENTS.md) и [порядок переноса](PORTING_WORKFLOW.md).

## Файлы проекта

| Папка | Назначение |
|---|---|
| `src/` | Код сайта и данные, которые он импортирует. `main.ts` связывает интерфейс; `codec.ts` и `native-*` работают с TSC; `solver.ts` и `spice.worker.ts` выполняют расчёты. |
| `tests/` | Проверки форматов, численных результатов и пользовательских сценариев. |
| `tools/` | Извлечение данных, подготовка эталонов и проверочные сценарии; [указатель](tools/README.md). |
| `docs/` | Актуальная документация проекта; `docs/archive/` — сохранённые прежние планы. |
| `reports/` | Технические свидетельства: снимки, сравнения, нативные эталоны. Датированные записи описывают состояние на дату проверки. |
| `work/` | Локальные черновики, временные сценарии и резервные копии; не публикуются. |
| `output/` | Личные учебные отчёты и комплекты файлов; не часть сайта и не публикуются. |
| `data/` | Локально извлечённые данные установленной TINA; не публикуются. |
| `dist/`, `node_modules/` | Результат сборки и зависимости; не редактируются вручную и не включаются в Git. |

`BrowserTransfer/project` — рабочий источник. `HostedTina` рядом — Git-зеркало публикации, а не вторая ветка разработки. Его `src/library.json` отличается: в публичном каталоге меньше моделей. Наличие модели или функции локально не доказывает наличие на сервере.

Текущий `vite.config.ts` использует **`data/` как publicDir**. Папка с именем `public/` автоматически в эту сборку не копируется. Не переносить туда ресурсы в предположении, что Vite их опубликует.

## Запуск и проверка

`npm ci`, затем `npm run dev` запускают локальный сайт. `npm run build` проверяет TypeScript и собирает приложение. Численные/TSC проверки выбираются по изменённому механизму; интерфейс проверяется реальным сценарием. Успешная сборка сама по себе не означает совместимость с TINA.

Не копировать рабочую папку в Git-зеркало целиком. Переносить проверенные исходники выборочно, сохраняя публичный каталог и исключая личные схемы, `work/`, `output/` и извлечённые данные.
